Iterable في Java

ملخص مختصر: شو هو، كيف بيشتغل، وكيف تحذف منه بأمان.

الفكرة

Iterable واجهة (interface) بتخلي الكلاس تبعك قابل للمرور عليه بحلقة for-each. فيها ميثود وحدة بس:

public class Library implements Iterable<Book> {
    private List<Book> books = new ArrayList<>();

    @Override
    public Iterator<Book> iterator() {
        return Collections.unmodifiableList(books).iterator();
    }
}

for (Book b : library) System.out.println(b);

حلقة for-each هي Iterator من ورا الستارة: Java بتنادي iterator() ثم hasNext() وnext() بدالك.

مكان Iterable في هرم Collections

أخضر: Interface برتقالي: Class خط متصل: extends خط منقط: implements

جواب علامات الاستفهام: Iterable في أعلى الهرم، وCollection بترث منها (extends). يعني كل شي تحت Collection هو Iterable تلقائياً: List وQueue وSet وكل كلاساتهم. هذا سبب إن ArrayList وHashSet بيشتغلوا مع for-each بدون ما تكتب شي.

الواجهةمميزاتهاأمثلة

Mapمفتاح وقيمة، مو IterableHashMap · LinkedHashMap · TreeMap · Hashtable
  • Map منفصلة عن الهرم، فما بتقدر تكتب for (x : map). بتمر على map.keySet() أو map.values() أو map.entrySet().
  • Stack بترث من Vector (خط متصل)، وLinkedList بتنفذ List وDeque معاً.
  • في مشروعك، Library بتنفذ Iterable مباشرة لأنك بس بدك المرور، وما بتحتاج كل ميثودات Collection مثل add وremove المكشوفة.

ليش تستخدمه

  • تغليف: ما بتكشف القائمة الداخلية بـ getBooks().
  • مرونة: بتغير List إلى Set وكود Main ما بيتأثر.
  • تحكم: الكلاس هو المسؤول عن قواعد الحذف والإضافة.
  • توافق: بيشتغل مع for-each ومع الـ Streams.

قواعد للتذكر

  1. next() مرة وحدة بكل دورة، وخزّن النتيجة بمتغير.
  2. الحذف أثناء المرور = it.remove() فقط.
  3. القائمة private وبدون getter.
  4. استخدم unmodifiableList لمنع الحذف من برّا.
  5. أي كلاس بدك تطبعه لازم فيه toString().
الخطوة الجاية: اكتب Iterator خاص فيك من الصفر.
